# Contributing

Use synthetic or explicitly redistributable examples. Do not submit proprietary solver inputs, credentials, private paths or unpublished results.
Describe observed behavior and expected behavior separately. Preserve the distinction between file integrity, execution completion and scientific validation.
Run `python -m unittest discover -s tests -v` before submitting changes. Add behavior tests for new parsing or validation rules.
Current scope is portable records and handoffs. Solver execution and automatic physical validation require separate designs.
